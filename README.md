## 为什么做这个

市面上的算卦工具，多数是"点一下出结果"的黑盒：你不知道它怎么起的卦，经文也常常抄错。

这个项目想做的是相反的事——

- **过程透明**。大衍筮法的每一次分二、挂一、揲四、归奇，算式都摆在界面上。
- **概率正确**。蓍草法和金钱卦的分布不同，这一点直接写在界面上，而不是偷偷用同一个随机数糊弄。
- **经文可信**。64 卦 384 条爻辞经过双数据源交叉校勘，每一处订正都有记录可查。

自用即可，不涉鬼神。

## 特性

- **两套起卦法，是真做了两套**
  - **金钱卦（标准）**：三枚铜钱掷六次，有翻滚动画
  - **大衍筮法（进阶）**：五十蓍草、虚一不用、三变一爻、六爻十八变，逐步展示算式
- **概率模型符合古法**
  - 蓍草法：老阳 3/16、少阴 7/16、少阳 5/16、老阴 1/16（30 万次抽样偏差 < 0.1%）
  - 金钱卦：老阳老阴各 1/8
  - 界面明示两者差异
- **完整经文**：卦辞、大象、动爻爻辞、彖传、小象，乾坤另录用九用六
- **宣纸风界面**：米黄纸底、墨色正文、朱砂标动爻，楷体经文配宋体标题
- **AI 解卦**：自带 API Key，支持任意 OpenAI 兼容接口，流式输出
- **多轮追问**：聊天框带着当前卦象的完整上下文，不会重新起卦
- **卦史**：本地自动存档，支持导出 / 导入 / 去重合并
- **单文件交付**：一个 HTML 走天下，双击即用，断网可用

## 快速开始

```bash
# 就是这样，没有安装步骤
open TaiYi.html        # macOS
start TaiYi.html       # Windows
xdg-open TaiYi.html    # Linux
```

或者直接把 `TaiYi.html` 拷到手机上、发给朋友——它自己就是完整的应用。

**AI 解卦**需要额外一步：点右上角「设置」填一个 API Key。不填也能正常起卦、看经文，只是没有 AI 解读。

## 使用说明

### 起卦

1. （建议）在「所问何事」里写下你要问的事。填了更准，不填也能起。
2. 选起卦方式：**金钱卦**（快）或 **大衍筮法**（慢，但正）。
3. 点主按钮，自下而上一爻一爻地起。嫌慢有「连摇六爻」和「十八变到底」两个快捷方式。
4. 满六爻自动成卦，跳到卦象面板。

起卦过程中的六爻是**自下而上**长的，动爻用朱砂标记：老阳记 ○，老阴记 ×。

| 铜钱 | 名称 | 爻 |
|:---:|:---:|:---:|
| 一背二字 | 单 | 少阳（阳，不动） |
| 两背一字 | 拆 | 少阴（阴，不动） |
| 三背 | 重 | 老阳（阳，动） |
| 三字 | 交 | 老阴（阴，动） |

### 解卦与追问

- 卦象面板先给**原文**：卦辞、大象、动爻爻辞（朱砂高亮），彖传和小象在折叠区里。
- 点「请解卦」，模型按四节输出：卦象解析 → 动爻定位 → 就事论事 → 一句断语。
- 解完卦下面就是聊天框，直接追问。它会带着这一卦的全部上下文回答，不会重新起卦。
- 经文是本地数据，解读是模型生成的——这一点界面上也标了。

### 卦史

- 每起一卦自动存档：时间、所问、起卦方式、本卦变卦、动爻、AI 解读全文。
- 「导出」下载一个 JSON，**只含卦例，不含 API Key**。
- 「导入」合并去重，脏数据自动丢弃。
- ⚠️ 卦史存在浏览器的 localStorage 里，**不随文件走**。换电脑、换浏览器、换打开方式都会看不到，要带走请先导出。

## 配置 AI 接口

「设置」里三个字段：

| 字段 | 说明 |
|:---|:---|
| 接口地址 | 任意 OpenAI 兼容的 `/chat/completions` 端点，默认 DeepSeek |
| 模型名称 | 如 `deepseek-chat` |
| API Key | 只存在你自己浏览器的 localStorage，文件里没有它 |

地址可以只填到域名或 `/v1`，脚本会自动补全 `/chat/completions`。

> **关于跨域**：如果点解卦报"连不上接口"，可能是该服务不允许浏览器直接调用。
> 换一个支持跨域的接口即可；必要时可以自己在本地跑一个转发代理。

## 项目结构

```text
TaiYi/
├── TaiYi.html               # 交付物：自包含单文件，唯一入口，双击即用
├── src/                   # 源码（改这里）
│   ├── index.html         #   页面骨架
│   ├── assets/style.css   #   宣纸风设计系统
│   ├── assets/app.js      #   起卦 / 解卦 / 追问 / 卦史
│   └── data/zhouyi.js     #   64 卦 · 384 爻数据表
└── tools/                 # 构建与自检脚本
    ├── build-data.js      #   数据清洗 + 一致性自检
    ├── selftest.js        #   概率分布 + 卦象查表 + 记号几何
    ├── bundle.js          #   src/ → TaiYi.html
    ├── smoke.js           #   jsdom 无头冒烟测试
    └── raw/               #   原始数据、校勘日志、测试报告
```

**为什么有源码和产物两份**：源码拆开才好维护（光数据就 75 KB）；打包成单文件才好用（不怕漏拷 `assets/` 目录）。改了源码一定要重新 `bundle`，否则交付的是旧版。

## 开发

纯前端，没有框架、没有构建工具、没有包依赖。脚本只需要 Node。

```bash
# Node 解释器（本机路径，版本会变，用前先确认）
NODE="C:/Users/86151/.workbuddy/binaries/node/versions/22.22.2-6/node.exe"
export NODE_PATH="C:/Users/86151/.workbuddy/binaries/node/workspace/node_modules"

# 1. 数据校勘（改了 data 才需要跑）
"$NODE" tools/build-data.js

# 2. 算法与数据自检
"$NODE" tools/selftest.js

# 3. 打包单文件
"$NODE" tools/bundle.js

# 4. 无头冒烟测试
"$NODE" tools/smoke.js
```

四条都跑绿再交付。测试报告在 `tools/raw/*.log`。

**改代码时两条铁律**：

1. 不要用 ES module——`file://` 下会被 CORS 拦掉，用传统 `<script src>`。
2. 起卦是「动画 + setTimeout 落定」的异步过程，落定回调里必须再查一次 `S.yao.length >= 6`，并且带 `castRun` 代号。详见 `src/assets/app.js` 里的注释。

## 数据来源与校勘

**交付物里的全部经文，只来自一个上游，且是 MIT 许可：**

| | |
|:---|:---|
| 唯一数据源 | [freizl/yijing](https://github.com/freizl/yijing) 的 `zh-CN/64gua.json` |
| 许可 | MIT，Copyright (c) 2023 - Present Haisheng Wu |
| 简繁统一 | opencc-js（"乾"等字做了保护，不会被误转成"干"） |

> **关于另一个数据源**：校勘阶段曾用 [john-walks-slow/open-iching](https://github.com/john-walks-slow/open-iching)
> 的 JSON 做离线对照。该仓库**没有许可证文件**，其 README 明确写着
> 「数据采集自互联网，仅供学习交流使用，不得用于商业用途」，且数据系从电子书爬取而来。
> 因此它的数据**不随本仓库分发**——`tools/raw/` 下只保留 MIT 的底本。
> 《周易》经文本身是公有领域的古代文本，本项目的订正均为通行本读法，
> 不涉及任何一方的独创性编排。

校勘方法：

1. **双源逐条比对**卦辞、爻辞、大象、彖传，差异处依通行本订正，共 **28 处**。
2. **结构性自检**：从爻辞里的爻名（初九 / 六二 / 上六…）反推各爻阴阳，再与卦象二进制逐位比对。这一招抓出了"大有卦九二被同人卦爻辞整条污染"这类错误。
3. **全量核对**：64 卦二进制互异无缺，384 条爻辞齐全。

订正明细见 `tools/raw/build.log`，双源差异全记录见 `tools/raw/diff.log`。**订正表本身在 `tools/build-data.js` 里，是唯一的真相来源**——日志只是它的输出快照。
